2. ENTITY FRAMEWORK CORE & DATABASE MODEL FIXES
--------------------------------------------------------------------------------
1.1 Notification.Data Property Ignored from Database Mapping
- File: VendorHub/Models/Notification.cs
- Issue: EF Core attempted to map Dictionary<string, object> Data as an unconfigured 
  entity, causing model building errors during migrations.
- Fix: Added [NotMapped] attribute to Notification.Data.

1.2 Composite Key Configuration for Favorite Entity
- File: VendorHub/Models/VendorHubDbContext.cs
- Issue: Favorite entity had dual primary keys (CustomerId and ProductId) without 
  a single [Key] property, causing EF Core model initialization failure.
- Fix: Configured composite primary key in OnModelCreating:
  modelBuilder.Entity<Favorite>().HasKey(f => new { f.CustomerId, f.ProductId });

1.3 Inverse Navigation on OrderItem Relationship
- File: VendorHub/Models/VendorHubDbContext.cs
- Issue: OrderItem configuration used .WithMany() without specifying p.OrderItems, 
  causing EF Core to create a duplicate shadow foreign key column ProductId1.
- Fix: Configured explicit inverse navigation property:
  modelBuilder.Entity<OrderItem>()
      .HasOne(oi => oi.Product)
      .WithMany(p => p.OrderItems)
      .HasForeignKey(oi => oi.ProductId)
      .OnDelete(DeleteBehavior.Restrict);
